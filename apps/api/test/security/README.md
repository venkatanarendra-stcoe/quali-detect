# Security regression suite

Run: `pnpm test:security` (from the repo root). Decision and scope: `docs/decisions/ADR-008-SECURITY-REGRESSION-SUITE.md`.

It covers **only** (ADR-008 areas 1 to 17; area 17, added by the owner in part I of the Executions plan, is execution lifecycle integrity, worker credential isolation, realtime authorization, the log and artifact stores and execution API scoping and pagination) tenant isolation, the 404/403 authorization rule, platform/tenant session separation, segregation of duties and the sign-in/MFA throttling of ADR-010 (plus, from the execution module, worker ownership and claim re-validation, credential absence, lease fencing and the stale-queue guarantee, and from part D cancellation and retry: another tenant's execution is a 404, quota released exactly once, a retry never bypasses a gate, a quota or the trust of a fork): 598 checks (775 with the later additions listed under Rules), 18 controls and 1 integrity test. It is a black box over HTTP, so it works against any implementation of the API (Fastify today, Express after ADR-007).

## What it needs

- PostgreSQL server binaries (`initdb`, `pg_ctl`): found through `PG_BIN_DIR`, `/usr/lib/postgresql/*/bin` or `PATH`. The runner starts an **ephemeral** cluster on a free port in a temporary directory and deletes it afterwards. No Docker.
- or `SECURITY_TEST_DATABASE_URL`: an existing, empty, **disposable** database. The runner refuses a database whose name does not contain "test" and never prints the URL.
- Nothing else: no Redis, no RabbitMQ, no `.env` files. Passwords and the MFA code are random for each run.

Development aid: `SECURITY_SUITE_ONLY="PIP-" node apps/api/scripts/security-suite.js` runs only the checks whose name matches (the integrity test is skipped unless it matches too). A filtered run never replaces the full `pnpm test:security`, which is the gate.

Exit codes of the runner (`node apps/api/scripts/security-suite.js`): `0` passed, `1` a check failed (the last API log lines are printed), `2` the environment is unusable (the message says why). Through `pnpm test:security`, pnpm reports `1` for any non-zero exit, so read the message to tell the two apart.
