## Built

### 1. The agent: `apps/workers/src/findings-agent/` (no `main.js` yet)

| File | What |
|---|---|
| `advise.js` | `runAdvisory({ message, repository, llm, config, limiter, rateLimiter, now, signal, logger })`: SPEC 9.3.1 steps 1 to 8. Returns `{ outcome: dropped / not_applicable / duplicate / rate_limited / stored, status?, advisoryId?, finding? }` |

Imports nothing from `@qmentisai/db`. | `prompt.js`, `output.js` | fixed system prompt (constant, the data is untrusted), the one tool `submit_advice`, the whole-output-or-nothing validator `validateAdvice` (exactly one call, strict `advisoryOutputSchema`, reasoning cleaned) |
| `harden.js` | `redactExtraShapes`, `hardenAdvisoryInput`: extra redaction layer (see "Deviations" 2) |
| `controls.js` | `createConcurrencyLimiter(max)` (FINDINGS_AGENT_MAX_CONCURRENT_CALLS), `createTenantTokenBucket` (30/min per tenant; in process), `startOfUtcDay` |
| `constants.js`, `index.js` | bounds (2 turns, 30 s, 400 output tokens), the barrel |

**Behaviour, in order:** load by tenant, workspace, repository, pipeline and id (a mismatch of any chain id, or a row of another tenant, is `dropped`); `agentRunsOn` false (secret, info) is `not_applicable`: no row, no provider resolved, zero requests; read the two consents by the **tenant of the row**; `egressLevelFor`; build the input (only a **SAST** finding may carry an excerpt) and harden it; `input_hash = advisoryInputHash({ v, level, providerKind, input, [hour bucket when manual] })`; a stored hash is `duplicate`; level `none` stores `not_configured`, `skipped_untrusted` or `consent_required` with zero requests; daily cap (`skipped_cap`); the per-tenant bucket (`rate_limited`, no row); resolve the provider; the provider is wrapped so **both consent tiers are re-read immediately before every request** and a request that would now carry more than the consents allow is stopped (`consent_required`); `runBoundedToolLoop`; validate; one `insertAdvisory`. The stored `egressLevel` is what was actually sent (`local`, `snippet`, `metadata`, `none`). Provider and model failures are stored statuses (`timeout`, `invalid_output`, `failed`); an **infrastructure** error (the repository) propagates so the queue retries.

## Deviations from the specification and why

1. **The prompt is the one thing the harness sees as a second turn:** `runBoundedToolLoop` answers a tool call with a tool-result message and a second provider call, so a successful advice makes **two** HTTP requests to the provider (the second carries the tool result only, no new data). Spec 9.3.5 says "2 turns", so this is as specified; stated because a "zero requests" check counts conversations.
2. **An extra redaction layer (`harden.js`).** The shared `buildAdvisoryInput` (frozen) and the platform `redactLogText` cover GitHub tokens, AWS access key ids, URLs with credentials, bearer tokens and private keys only. The scan-engines canaries for Stripe keys, Slack tokens, JWTs, a quoted `secret = "..."` value were **not** redacted and reached the request in my first check run. The worker now adds those shapes (and re-validates the strict schema). **Defect to report, not fixed here (the shared package is frozen and its shapes mirror the database CHECK):** the shared credential shapes are narrower than the secret classes of the scan engines. A source excerpt can still hold a secret no pattern knows; that residual risk is why an external provider needs the second consent, and why secret findings never run.
3. **`input_hash` includes the egress level, the provider kind and (for a manual request) the hour.** Otherwise a stored `consent_required` row would block the real advisory after the tenant consents, and a failed row would block a manual retry (the unique key is `(finding, input_hash)`). `advisoryInputHash` itself is unchanged.
4. **The rate limit has no row.** A rate-limited request stores nothing and is retried through the queue's retry tiers (`TransientError`); the daily cap does store `skipped_cap`.
5. **Only SAST findings can carry an excerpt** (SPEC 14.1: "SAST snippets are sent, SCA none"); `buildAdvisoryInput` alone would send one for SCA if a row existed.
6. **Not built, by assignment:** `main.js`, the `ownership` entry, the advisory route (`POST /findings/{id}/advisory/request`), the DTO mapping, `advisories.js` bodies, `packages/infra` consent port (the port is built in `runtime.js` and the JSDoc of `resolve.js` is untouched: the resolver needs only `isExternalAllowed`).
