## 2. Decisions and deviations

1. **`meta` needs its own read.** The shared API client returns `data` only; every reporting read needs `meta` (`asOf`, `source`, `stale`, `timeZone`). `readWithMeta` in the service reads the envelope itself with the client's rules (cookie, correlation id, `ApiError`, a 401 reaches the shared handler through one `GET /me`). In development every response is checked against `REPORTING_ROUTE_SCHEMAS` (logged, never thrown). Proposal for the shared client: a `getWithMeta`.
2. **Charts:** `--sev-*` tokens in the order Critical to Info with a pattern per severity, `--chart-1` only for the one primary series (Fixed), neutral chart tokens plus patterns for lifecycle groups (they are statuses, never the accent), `--status-*` for SLA and execution states, no hex anywhere. Every chart keeps Recharts' accessibility layer (arrow keys move point by point, tooltip follows), has a one-sentence summary, a Chart/Table toggle, a text legend with values, "no data" bands for days before the first rollup day (never a zero).
3. **Not in the DTOs, so not built (each said on screen where relevant):** per-day duration trend and completeness by scan type (S-3, S-6 are period totals); FP rate by month; repository and pipeline names, provider, default branch, duration in T-21 tables (breakdown rows carry labels and last scan only); workspace on top-risk rows (so the Overview row is not a link); SLA state and pipeline on the oldest-findings list; tenant-wide trend (the Overview sums the trends of up to 10 workspaces it can see and says so; above 10 it shows a not-available card); advice split by human decision for "uncertain"; the O-4 "count distinct issues" toggle (no read parameter exists); severity and status filters and the assignee option in Generate (the strict body has only `options.distinctIssues`; the assignee column follows the caller's `finding.assign`); a row estimate exists only for Findings by pipeline and SBOM (from posture and SBOM counts); SHA-256 in T-51 (not in `reportRunDtoSchema`); a separate "Name" and "Template" column (one `Report` column); numbered pagination (the list is cursor based: "Load more"); template and "mine" filters are client side over loaded pages (the API filters status only); "AI advice is turned off" banner is inferred (no outcome other than not configured).
4. **Drill-down URLs** use only parameters `readFindingFilters` accepts: `view` (`all_open`, `breached_sla`), `severity`, `status`, `sla`, `pipeline`, `repository`, `assignee`. **Not expressible, so plain text:** age buckets (R-6), new in 24 hours (P-9), fixed in the period, exceptions expiring in 30 days, a combined "status group AND severity". Awaiting approval links to Approvals. Count equality against the real list was not checked (no API).
5. **Focus return:** Radix returns focus to a `Trigger` that these state-opened dialogs do not have; `useReturnFocus` restores it. Table cells are module-level components reading a context (inline cell functions remounted every cell on each 5 s poll and dropped focus).
6. Light-theme contrast: `text-subtle-foreground` on the page background measured 4.31:1; the helper line and the data footer use `text-muted-foreground`.

## 5. Round 2 (amended DTOs, `AS_BUILT_AM.md`)
