# Screens: repositories and GitHub integration

Status: **Implemented** (2026-11-12), companion to `SPEC.md` (§18 amendment, ADR-012). This document describes the screens **as built**; the wireframe (`docs/TENANT_APP_WIREFRAME_SPEC.md` §5, §6) is the source of the identifiers and layouts, and the differences are listed at the end. Visual rules: `DESIGN_SYSTEM.md`, `UX_GUIDELINES.md`.

Common rules (**Confirmed**): visibility comes from the central engine, never role names; an action the user can never perform is hidden, one they may reasonably request is disabled with a tooltip naming the permission; no counts or names of resources the user cannot access; every data view has loading, empty, error (with correlation id) and no-permission states; filters, sorting and the page live in the URL; query keys start with the tenant (and the workspace id); mono only for identifiers; status chips have an icon and text.

## T-13 Integrations
Tenant-wide tools by category tabs (All, Source control, AI coding tools, Ticketing, Collaboration, Security tools, Cloud, Secrets): only GitHub is live, every other provider shows "Not available yet" with a disabled button and a tooltip. A **Source control** section lists the organization's GitHub installations read-only: account (mono), type, repository selection, status, repository count and the workspaces that use each (names only for workspaces the caller can see, "+N more" for the rest). There is **no Connect button at organization level**: the text says "Source control is connected from a workspace's Integrations page". The switch **"Allow workspace admins to link source control"** (default on) is editable with `integration.manage`, read-only otherwise, and audited by the API. States: loading, error with retry, unauthorized, "No GitHub account linked", "GitHub is not configured".

## T-14 GitHub installation detail
Read-only: header, per installation the account, type, repository access (all/selected), permissions granted, first-linked date, repositories in QmentisAI, the workspaces using it and the **Webhook health** table (installation-level deliveries: time, event, outcome, signature verified; outcome filter and paging). No Link, Test connection, Unlink or Scope controls exist here.

## T-42 Workspace Integrations (the connect page)
- **Link a GitHub account** (primary; disabled with the organization's message when the tenant setting is off, with the permission reason without `workspace_integration.manage`) opens a choice: **Install the App on a GitHub account** (`start`, GitHub install page) or **Use an existing installation** (`discover`). Before leaving for GitHub the page stores the workspace id as a hint in session storage.
- Each **workspace link** shows account (mono), type, health pill, repository selection, allowed and connected repository counts, last event time, and the actions **Test connection**, **Unlink** (typed account login; explains that only this workspace's repositories are disconnected and can be restored by linking again) and the **repository allow-list editor** (searchable, paged installation repositories with checkboxes; repositories on another workspace's list are disabled with the reason, connected repositories are locked with a note; saving surfaces a 409 with the server message, clears stale selections and refreshes the list).
- Read-only for `workspace_integration.view` holders, with the reason on every disabled action. States: loading, "No GitHub account linked" (with the actions or the explanation of whom to ask), "GitHub is not configured", error with retry, no-permission.

## Setup and callback landing pages
`/integrations/github/setup?installation_id=` reads only a hint, picks the workspace (hint from session storage, otherwise a picker among the workspaces where the user holds `workspace_integration.manage`) and calls the workspace `authorize`; without an id it offers the same two choices as T-42. `/integrations/github/callback?code&state` posts `{code, state}` **once** (StrictMode safe), clears the URL and the hint and shows: `201` success (toast, opens that workspace's T-42); or `200 { mode: "discover" }` the **Use an existing installation** list (one row per candidate with account, type, selection, a Suspended badge; "Already linked here" and "Only an owner of the organization can link it" rows are disabled; **Use this installation** starts the normal flow for that id; a truncated answer says only the first organizations were checked); or an error with **Start again** (state invalid/expired/used, no permission, the setting-off wording for `workspace_linking_disabled`, the generic "This GitHub installation cannot be linked." for the cross-tenant 409). Empty discovery: "No installation of the App found for your GitHub account. Install the App on a GitHub account."

## T-22 Repositories list
Header action **Connect repository** (hidden/disabled by `repository.connect`); toolbar search, Health filter (Healthy, Degraded, Unavailable, Disconnected) and Status filter (Active, Unavailable, Disconnected); table: full name (mono) with visibility, default branch, health pill (Healthy, Degraded, Unavailable, Disconnected, Disabled), last synced, pipelines count (0 until the Pipelines module) and row actions (Open, Sync now, Enable/Disable, Disconnect with the typed full name). Sort, filters and the page are in the URL. Empty states: "No repositories connected" (with Connect and a link to the workspace's integrations) and "No matching repositories" with Clear filters; error; a workspace the user cannot see is the not-found page.

## T-23 Connect repository
1 **Provider**: GitHub account select, listing this workspace's linked accounts (no account: the explanation and a link to T-42 for `.manage` holders), with the note "Events arrive through the GitHub App. Signatures are verified on every delivery."; 2 **Select repositories**: search and paged list of the **allow-listed** repositories of the chosen link ("Already connected" rows disabled; an empty allow-list explains and links to T-42 for `.manage` holders; provider outage shows an error with retry); 3 **Review**: the selection with per-repository status, **Connect N repositories** (one request per repository with its own `Idempotency-Key`, reused on **Retry failed**) and Done.

## T-24 Repository detail
Header: full name (mono), health pill and the actions **Sync now**, **Enable/Disable**, **Disconnect** (typed full name), each by permission. Banners for `unavailable` (failure count and recovery) and `disconnected` (since when, reason; mentions the workspace unlink or the uninstall). Tabs: **Overview** (provider, visibility, default branch, connected, last synced, last event, pipelines 0, link to GitHub), **Branches** and **Pull requests** (live from GitHub through the API, titles as escaped text), **Webhooks** (events arrive through the App; last event time; link to the installation's delivery history) and **Settings** (display name and description with `repository.update`). A repository opened under a workspace that does not own it is the not-found page. Add pipeline, Commits and the findings parts arrive with their modules.

## Differences from the wireframe
1. T-13/T-14/T-42 follow ADR-012: the GitHub link lives in the workspace (WF showed it at organization level), organization pages are read-only.
2. WF `repository.create` is `repository.connect`; WF "Disconnect" for an integration is **Unlink** (workspace-scoped); "Test connection" maps to `POST .../refresh`; the WF text "Webhooks will be registered automatically" is replaced for an App.
3. Wireframe columns and tabs that depend on pipelines, executions, findings and commits (T-22 last execution, open findings, last commit; T-24 Pipelines, Commits, Add pipeline) are not shown until those modules exist; T-22 has no Provider filter (GitHub is the only provider); T-24 has no access-restriction control (`repository.manage_access` is not exposed yet).
4. The wireframe's `/integrations/:provider` is `/integrations/github` (one provider).

Headless Chrome against a disposable stack (own PostgreSQL, local GitHub stub, API and Vite on private ports), all seven seeded roles signed in. Flows verified end to end (stubbed GitHub): Manager (no tenant Admin) links a new account from T-42 (start, setup, authorize, callback, lands on T-42 with a toast, hint and URL cleared, exactly one `POST /integrations/github/links`); Admin links the same installation from a second workspace (no conflict); allow-list editing (search, selection kept across searches, save toast, repositories on another workspace's list disabled with the reason, connected repositories locked with a note); a stale-page conflict (409) shows the server message and refreshes the list; the wizard shows only allow-listed repositories, explains an empty allow-list with a link to T-42 for `.manage` holders, connects one repository with `workspaceLinkId`; unlinking in one workspace (typed login) disconnects only its repositories and leaves the other workspace's link intact; T-24 of a disconnected repository mentions the workspace unlink; tenant setting off disables Link with the organization's message on T-42, on the setup page and on the callback (403 `workspace_linking_disabled`); bad state and missing parameters show an error with "Start again"; setup without hint asks for a workspace among those with `.manage`; workspace switch keeps T-42 when the target allows it and resets to the Dashboard otherwise; loading, empty (new workspace), error (500 after retries) and no-permission states; no horizontal page overflow at 390, 820 and 1440 px on T-13, T-14, T-42 (editor open), T-23 step 2, T-22, T-24 and the setup picker.

Not exercised against a real second tenant: the generic 409 `installation_unavailable` on the callback was checked with a mocked response only. T-13/T-14 hidden-workspace counts ("+N more") are rendered from `hiddenWorkspaceCount` but only an Admin (sees all workspaces) can open those pages with the seeded roles.

Defects found and fixed in this pass: the T-13 provider card status badge overflowed by 1 px at 820 px; allow-list rows wrapped the repository name badly at 390 px; after a 409 the editor kept stale selections (now cleared and the list refreshed); "1 repositories disconnected" pluralization.

Known display limitation (SPEC §16.2, deferred): an installation that was uninstalled or suspended on GitHub can still read "linked" at the workspace-link level in T-13/T-14/T-42; its health pill (Revoked/Suspended) is correct, the status text, date and reason are not yet shown everywhere.
