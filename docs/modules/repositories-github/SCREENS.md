Common rules (**Confirmed**, WF §4.1/§4.5/§4.6 and `UX_GUIDELINES.md`): visibility comes from the central engine (never role names); an action the user can never perform is **hidden**, one they may reasonably request is **disabled with a tooltip naming the permission**; never show counts or names of resources the user cannot access; every data view has loading, empty, error (with correlation ID) and no-permission states; filters, sorting and the page live in the URL; query keys start with the tenant and include the workspace id; mono only for identifiers (repository names, SHAs, ids); status chips have an icon and text; mint only for the primary action. Navigation: `integrations` (organization) and `repositories` (workspace) are `implemented: true`; `workspace-integrations` flips to `implemented: true` with this work.

## T-13 Integrations catalog
- **WF prompt (§6):** category tabs All, Source control, AI coding tools, Ticketing, Collaboration, Security tools, Cloud, Secrets; a grid of cards (logo placeholder, name, short description, status pill Connected / Degraded / Not connected, button Connect or Manage); AI coding tools carry a "Beta" badge.
- **Implemented now:** the full catalog is rendered from a static list; **only GitHub is live** (status from `GET /integrations/github`: Connected when at least one link is `linked`, Degraded when any linked installation is suspended or has unavailable repositories, otherwise Not connected). Every other card shows "Not available yet" with its button disabled and a tooltip, so no capability is implied (`INTEGRATION_ARCHITECTURE.md`, TAD §3.14).
- **Actions:** Manage/Connect on GitHub opens T-14 (users without `integration.manage` see the detail read-only).
- **States:** loading; error with retry; unauthorized (the Administration group is hidden without `integration.view`); App not configured on the platform -> GitHub card shows "Not configured by your platform administrator".

## T-14 Integration detail (GitHub)
- **WF prompt:** header with logo, name, status pill and buttons Test connection and a destructive Disconnect; sections Connection (installation/organization name, auth method, connected by, connected on; never tokens), Capabilities, Scope (which workspaces may use this connection, multi-select), Webhook health (last delivery, success rate, recent deliveries table with signature verified), Events log.
- **Implemented:**
  - **Header:** GitHub, status pill (Healthy / Degraded / Suspended / Revoked), buttons **Test connection** (`POST .../refresh`) and **Unlink** (destructive, typed account login, server-checked; explains that the App stays installed on GitHub, repositories become disconnected and can be restored by re-linking). WF's "Disconnect" is named **Unlink** to match the approved semantics (SPEC R-6).
  - **No linked account yet:** an empty state with **Link a GitHub account** (primary): `start` -> GitHub install page -> setup redirect (`/integrations/github/setup?installation_id=`) -> authorize -> callback (`/integrations/github/callback?code&state`) -> result page showing success or the specific refusal (not an organization admin / not your account / already linked elsewhere with the generic wording). Both landing routes show a progress state and never display codes or ids from the URL after use.
  - **Connection:** account (login, type), repository selection, permissions granted (read-only list), connected by, connected on, authentication method "GitHub App installation", and the line "No credentials are stored for you: access uses short-lived tokens".
  - **Capabilities:** checklist from the installation's granted permissions (Webhooks ✓ via the App, Repository metadata, Contents read, Pull requests read; Commit status / PR comments shown as "Not requested").
  - **Scope:** multi-select of workspaces (empty = all) saved with `PUT .../workspaces` (needs `integration.manage`; otherwise read-only).
  - **Webhook health:** last delivery time, success rate over recent deliveries, recent deliveries table (time, event, outcome, "signature verified"), from `GET .../deliveries`; **Events log** is the same table with outcome filter.
- **Permissions:** read with `integration.view`; every action needs `integration.manage` (hidden for viewers, WF §4.4: Administration is Admin-only by default).
- **States:** loading, error, unauthorized, empty (no deliveries yet), degraded banner with the recovery step.

## T-22 Repositories list (workspace)
- **WF prompt:** header button **Connect repository**; toolbar search, Provider filter (GitHub, GitLab, Bitbucket), Health filter; table: provider icon + full name (mono), default branch, Pipelines count, Last execution status, Open findings mini severity badges, Connection health pill, Last commit (short SHA + relative time), row actions; empty state "Connect your first repository" with provider buttons.
- **Implemented now:** provider icon + full name, default branch, **Pipelines count (0, "planned")**, Connection health pill (Healthy / Degraded / Unavailable / Disconnected / Disabled), Last event time, row actions (Open, Sync now `repository.sync`, Disable/Enable `repository.toggle`, Disconnect `repository.disconnect`). Last execution, Open findings and Last commit columns appear when the pipelines/findings modules and push data exist (shown as "-" with a tooltip until then). Provider filter lists GitHub and shows GitLab/Bitbucket disabled ("not available yet"). Filters: search, provider, health, status; sorting; pagination (URL).
- **RBAC (WF §4.4):** every role sees the page; Admin, Manager, Dev Lead see Connect; Lead, Security Analyst, Developer, Viewer see it read-only (Connect hidden when the user can never connect, disabled with a tooltip otherwise); row actions follow `repository.sync/toggle/disconnect` per workspace.
- **Empty state:** "Connect your first repository" with the GitHub button; if GitHub is not linked and the user has `integration.manage` it links to T-14, otherwise it explains whom to ask.
- **States:** loading, filtered-empty with Clear filters, error, no-permission (workspace not visible -> not-found state, never 403 wording).

## T-23 Connect repository (3-step wizard)
- **WF prompt:** stepper 1 Provider, 2 Select repositories, 3 Review; step 2: provider GitHub with its connection name, a searchable list with checkboxes, visibility badge (Private/Public), default branch, "Already connected" disabled rows; right summary card (target workspace, number selected, note); footer Back / Continue.
- **Implemented:** 1 **Provider**: GitHub (selectable, with the linked account chip(s); GitLab/Bitbucket disabled) and, when more than one installation is linked, an account picker (only links whose workspace scope includes this workspace); no link -> the empty state of T-22; 2 **Select repositories**: search, visibility, paged list from `.../available` (provider outage -> error state with retry), rows already connected anywhere in the tenant disabled; 3 **Review**: target workspace, repositories, per-repository optional display name/owner/description, the note **"Events arrive through the GitHub App. Signatures are verified on every delivery."** (replaces the WF text "Webhooks will be registered automatically", which does not apply to an App) and the entitlement hint (`repositories.max`). Submission calls `POST /workspaces/:id/repositories` once per repository with an `Idempotency-Key`; the result view lists each repository with Connected or the stable error (already connected, quota, provider unavailable) and **Retry failed**.
- **RBAC:** reachable with `repository.connect` in the workspace; the entry button is hidden for roles that can never connect and disabled with a tooltip otherwise.

## T-24 Repository detail
- **WF prompt:** header with provider icon, name (mono), default branch chip, health pill, buttons **Add pipeline** and **Sync now**; tabs Overview, Pipelines, Branches, Pull requests, Commits, Webhooks, Settings; Overview: languages bar, manifests, SBOM card, findings by severity, table of pipelines on the repository.
- **Implemented now (the rest is shown as planned tabs, no placeholders in navigation):** header (name, branch, health, **Sync now** `repository.sync`; **Add pipeline** is hidden until the pipelines module exists); **Overview** (repository information: visibility, archived, owner, workspace, linked account, last sync, last event, health with the failure reason and recovery steps, "Pipelines on this repository: 0, planned"); **Branches** and **Pull requests** (live from GitHub through the API, 60 s cache, titles escaped as untrusted text, provider-outage state); **Webhooks** (recent deliveries and events for this repository from the stored events: time, event, ref/PR, outcome); **Settings** (display name, description, owner with `repository.update`; Enable/Disable with `repository.toggle`; access restriction with `repository.manage_access`; **Disconnect** typed full name with `repository.disconnect`, explaining that history is kept and the same row is reactivated by reconnecting). **Commits** and the pipeline/findings parts of Overview arrive with their modules.
- **States:** loading skeleton; not-found for absent or not visible (identical); error; `unavailable` banner ("GitHub no longer returns this repository", failure count, the N-failure rule); `disconnected` read-only view with the reason.

## T-42 Workspace Integrations
- **WF prompt:** list of organization integrations enabled for this workspace with status pill, routing settings, and "Enable for this workspace" toggles; integrations not connected at organization level show "Connect at organization level" (admins only).
- **Implemented:** the linked GitHub accounts **the organization allows this workspace to use** (organization scope is the ceiling), each with a health pill and a **Use in this workspace** toggle that writes the workspace's own routing setting (`PUT /workspaces/{id}/integrations/{linkId}`). Read-only without `workspace_integration.manage`, with the reason shown. A link to the organization GitHub settings (T-14) appears only with `integration.view` (Admin). No linked or allowed account: an empty state that explains an organization administrator links accounts and chooses the workspaces.
- **RBAC:** `workspace_integration.view` (workspace scope) to open; `workspace_integration.manage` to toggle. The T-23 wizard reads the same list (only enabled connections) so Managers and Dev Leads can connect repositories without `integration.view`.

## Differences from the wireframe (resolved with the catalog; **Recommended — default applied**)
1. WF §4.4 shows Workspace Integrations to Manager (●), Lead and Dev Lead (◐). **Closed (2026-11-11, AUTHORIZATION Q26):** new workspace-scope keys `workspace_integration.view` (Admin, Manager, Lead, Dev Lead) and `.manage` (Admin, Manager) cover routing inside the workspace; organization-level connect/disconnect stays `integration.manage` (Admin).
2. WF `repository.create` is `repository.connect` (Q5, decided).
3. WF T-23 note about automatic webhook registration is replaced for an App (Q6).
4. WF T-14 "Disconnect" is "Unlink" (R-6, Q10); WF "Test connection" maps to `POST .../refresh`.
5. WF T-22/T-24 columns and tabs that depend on pipelines, executions, findings and commits are hidden or show "planned" until those modules exist (WF §4.3: unimplemented items stay hidden, no placeholder pages in navigation).
