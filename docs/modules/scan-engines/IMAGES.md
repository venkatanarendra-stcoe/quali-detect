## 4. Image policy and mirror registry (owner decisions of 2026-11-19, SPEC D-13, D-14)

- **Own-built images.** Opengrep and detect-secrets have no upstream image; the owner approved building our own (recipe: the release binary verified against its published sha256, or the frozen `pip` set listed in section 1, on a digest-pinned base image; non-root `USER`; no package manager or shell added beyond the base). The spike's local image ids are not registry digests: after the image is pushed to the mirror, **the registry digest is what goes into the lock file** (SPEC Part B flags a locally built entry as needing a registry digest before production).
- **Pinned platform mirror registry.** Every runnable image (upstream images included) is copied to a platform-controlled registry by digest and provisioned from there into the runtime store; the scan path runs with `--pull=never`. The registry hostname and credentials are provisioning-step details; they never reach a scan worker.
- **Data policy.** Vulnerability data for v1 follows SPEC 5.12.1: language ecosystems only, GHSA / NVD / OSV core, Grype DB and Chainguard data quarantined; Grype itself is deferred to v2 (D-21), so SCA v1 = Trivy (language ecosystems only, OS/distro scanning disabled) + OSV-Scanner. During the DB-mirror build, verify that the npm, PyPI, Go and Maven OSV zips contain no Chainguard/Wolfi or other non-commercial record and quarantine any that do (ENG-L19).
- **Excluded / deferred:** cdxgen stays excluded; Ruby SAST is deferred until a permissive option exists (SPEC D-17).

Verified facts (real output):

- **Trivy language-only.** `--pkg-types library` is accepted (`--pkg-types strings: list of package types (allowed values: os,library) (default [os,library])`); with it every `Results[]` entry is `Class: lang-pkgs` (`npm`, `pip`, `pom`, `gomod`). In filesystem mode Trivy detects no operating system (`Detected OS family="none"`, even with `/etc/os-release` and a dpkg and an apk database in the tree), so no `os-pkgs` result appeared with or without the flag; the flag is kept as the belt-and-braces switch, the engine's adapter DROPS any result whose class is not `lang-pkgs`, and a source guard (`ENG-S03d`) pins the flag in the argument vector. `--scanners vuln` only; `--list-all-pkgs=false` removes the `Packages` arrays (260 KB to 254 KB on tree A).
- **Trivy data used.** Language findings carry `SeveritySource` `ghsa` (or none for the Go database `govulndb`); `VendorSeverity` and `CVSS` also list `redhat`, `ubuntu`, `azure`, `bitnami` and `ruby-advisory-db` ratings of the same CVE. The mapper uses ONLY Trivy's own `Severity` and the `ghsa` and `nvd` CVSS entries; the other vendors' ratings are ignored. **Flagged for the legal gate (OQ-26 / ENG-L19): those vendor ratings are present inside the Trivy database file itself and cannot be removed from it.**
- **Trivy exit codes and errors.** 0 with and without findings (no `--exit-code`); a tree with no lockfile gives exit 0 and no `Results`; a missing or empty DB directory exits 1 with `--skip-db-update cannot be specified on the first run`; a corrupt file exits 1 with `failed to open db: invalid database`; both contain `DB error:` and are classified `db_unavailable` (transient). `--include-dev-deps` adds the npm dev dependency (tree C: 45 to 47 findings, `minimist@1.2.0`).
- **Repository configuration is not read.** A tree with a planted `.trivyignore` listing every CVE found, a `trivy.yaml` with `skip-dirs: **` and a `.trivy/vex.json`: output byte-identical to the clean tree except `ReportID` and `CreatedAt`.
