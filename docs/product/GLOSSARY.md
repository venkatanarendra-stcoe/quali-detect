# QmentisAI Glossary

| Term | Meaning |
|---|---|
| Tenant | Customer organization using QmentisAI |
| Workspace | Tenant-level grouping of repositories, users, pipelines and policies |
| Repository | Connected source-code repository |
| Pipeline | Independent security workflow configured for a repository |
| Execution | One run of a pipeline |
| Scan task | A scan operation within an execution |
| Finding | A pipeline-owned security issue identified by analysis or scanning |
| Fingerprint | Stable identifier used to recognize a finding across scans |
| Evidence | Supporting technical data for a finding or decision |
| True Positive (TP) | Finding confirmed as a genuine security issue |
| False Positive (FP) | Finding determined not to represent a genuine issue |
| Accepted Risk | A genuine issue whose risk is formally accepted for a defined period |
| Suppression | Policy-driven or approved hiding/exclusion of a finding from specified views or processing |
| Entitlement | Permission for a tenant to use a feature or capability |
| Quota | Usage limit associated with an entitlement or subscription |
| Root Console | Platform administration application |
| Tenant Application | Customer-facing security engineering application |
| Worker | Background process handling asynchronous workloads |

Use these terms consistently in APIs, database models, UI labels and documentation.
